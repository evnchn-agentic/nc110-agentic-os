**M1 — `session()` is not bounded by bmctl's idle timer once connected.**
In `session()`:
```
let mut last_pet = time::now_ms();
...
'outer: while (got_output || time::now_ms() < deadline)
        && (!cfg!(feature = "attended") || ctl.is_some() || time::now_ms() < hard_end) {
    if wdt::armed() && time::now_ms() - last_pet >= 1000 {
        wdt::pet();
        ...
```
The loop's exit conditions are: `got_output==false && now>=deadline` (60 s no-output cap) OR (`attended` features only) `ctl.is_none()` guard OR `hard_end` only applies when `!attended` is false — but in the `bmctl`-mode path `ctl.is_some()` is `true`, so `hard_end` is skipped (per comment: "`bmctl ssh` drops it; bmctl's idle bound plays that role instead"). That role is only realized if `c.step()` fires `Act::Idle`, i.e. only when *no authenticated command* arrives. But `session()` is petting on its own 1 s timer regardless of whether `Ctl::step` has been reached. So the claim "only the caller resets" holds — but only if the session loop is actually exiting on the idle deadline, which it does *not* while `got_output` and TCP stay alive, because bmctl's idle deadline only becomes `Act::Idle` when `c.step` returns it and `c.act` returns false. That is fine *provided* `step` runs. It does. So where's the bug?

The bug: **keyboard escalation via an SSH shell that hangs after output but never closes, in the default (non-attended) build**, is protected by "^bmctl idle drops it" — but `bmctl` idle only fires on `time::now_ms() - last_ok > idle_ms` where `last_ok` is bumped by *authenticated bmctl command*. Once `Ctl::new` is running and the operator stops issuing commands, that *does* fire. So M1 as a "petting forever" claim is **false** in normal operation, **false** if the DHCP-offer host never answers (60 s deadline covers no-output), **false** if connected but silent.

**The real gap is narrower:** when `cfg!(feature = "attended")` and `ctl.is_none()` (the standalone `ssh::run` path where bmctl is not present), the guard is `time::now_ms() < hard_end` = 180 s — fine. But when `ctl.is_some()` and the operator *keeps authenticated traffic flowing* (`last_ok` refreshed every < `idle_ms`), `last_pet` keeps the TCO fed while `Ctl::step` is also being called — that's the intended invariant, not a bug. So M1 is actually a **SO** (see below).
